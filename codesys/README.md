# Управление деаэратором — тестовый вариант

`FB_Deaerator.st` — исходник функционального блока для CODESYS 3.5.
Бинарный `BOILER_SIMULATOR.project` не изменён. Блок ещё не встроен в
проект и не скомпилирован в CODESYS: в облачной Linux-среде IDE отсутствует.

## Добавление в проект

Создать POU типа Function Block с именем `FB_Deaerator`, язык ST.
В область деклараций перенести VAR_INPUT, VAR_OUTPUT и VAR, а в реализацию —
код после последнего END_VAR, без FUNCTION_BLOCK/END_FUNCTION_BLOCK.
Нужна стандартная библиотека Standard (TON). Создать экземпляр блока и
вызывать его один раз за каждый цикл задачи, например каждые 100 мс.
Использовать существующий checkout; отдельный Git worktree не требуется.
Проверить сборку и работу сначала в симуляции CODESYS, без физических выходов.

## Алгоритм

Enable — постоянный запрос работы, Stop имеет приоритет. После разрешения
станция заполняется до 60 %, затем прогревается. После достижения минимум
103 °C и 0,17 бар переходит в режим поддержания. Ready вычисляется заново
каждый цикл и не является аварийной защитой или разрешением насоса.

Подпитка 1 включается при уровне ≤55 % и выключается при ≥65 %.
При первоначальном заполнении она выключается на 60 %.
Подпитка 2 дополнительно включается ниже 45 %. Предполагаются два независимых
параллельных клапана; если Q0.3 управляет иной схемой, это назначение нужно изменить.

Нагрев регулируется импульсами по 1 с с паузой 4 с. Открытие разрешается
при температуре ≤103 °C и давлении ≤0,20 бар; закрытие запрашивается
при температуре ≥105 °C или давлении ≥0,23 бар. Между порогами клапан
удерживает положение. Давление ограничивает нагрев, но само по себе не
вызывает открытие. При остановке, заполнении или охлаждении выдаются
повторные импульсы закрытия. Предполагается привод с собственными концевиками,
допускающий такие команды; время полного хода пока неизвестно.

Охлаждение включается при ≥110 °C, выключается при ≤107 °C и доступно
только при включённой станции. Оно управляется той же температурой VEM:
отдельного датчика охлаждаемого контура в исходной таблице нет.
Слив доступен при Stop или снятом Enable и удерживаемом DrainRequest;
выход отключается при уровне ≤5 %. Для повторного запуска снять запрос слива.
Сигнал второго уровня включается при ≥75 %, выключается при ≤70 %.

## Тестовые датчики и параметры

| Измерение | Тестовый диапазон | Единицы |
|---|---|---|
| Давление | 0…1 | бар избыточного давления |
| Уровень | 0…100 | % |
| Температура VEM | 0…150 | °C |

Блок принимает уже масштабированные инженерные значения. В симуляции
задавать их напрямую; привязку сырых значений МВ210-102 пока не выполнять.
Тип сигналов, формат регистров, адреса Modbus и модели датчиков не определены.
Для будущего датчика 4–20 мА формула: (IмА − 4) / 16 × диапазон + минимум.
Это условный пример, не подтверждённая схема подключения.
Температура 104 °C и давление 0,20 бар выбраны как тестовая пара,
а не как рассчитанные параметры конкретного деаэратора.
Параметры FB изменяются снаружи; сохранять согласованный порядок порогов
и положительные длительности. Автоматической проверки конфигурации пока нет.

## Подключение выходов

| Выход FB | Канал из README |
|---|---|
| HeatClose / HeatOpen | Q0.0 / Q0.1 |
| Feed1 / Feed2 | Q0.2 / Q0.3 |
| Drain | Q0.6 |
| StationEnabled | Q0.7 |
| SecondLevel | Q1.0 |
| Cooling | Q1.1 |

Q0.4, Q0.5 и вход контроля жёсткости/HART не используются новым блоком.
Существующую аварийную логику и её подключения сохранить. StationEnabled
и SecondLevel — обычные технологические сигналы, не защитные разрешения.
Физические адреса ПЛК210 и МВ210-102 нужно подтвердить в конфигурации устройств;
обозначения SM1233 из исходного README не являются адресами модуля ОВЕН.

## Проверки в симуляции CODESYS (предстоит выполнить)

1. Enable=FALSE: обе подпитки, охлаждение и StationEnabled выключены;
   слив выключен без DrainRequest, нагрев получает импульсы закрытия.
2. Enable=TRUE, уровень 20 %: State=10, обе подпитки включены,
   HeatOpen выключен. На 60 %: State=20, подпитка выключена.
3. На 60 %, 90 °C, 0,10 бар: появляются импульсы открытия с паузами.
   Ни в одном цикле HeatOpen и HeatClose не должны быть включены вместе.
4. На 104 °C, 0,20 бар: State=30, Ready=TRUE, нагрев удерживается.
   При 106 °C или 0,24 бар: импульсы закрытия.
5. В рабочем режиме: 54 % включает Feed1, 60 % сохраняет его включённым,
   65 % выключает. На 44 % включены обе подпитки, на 46 % — только первая.
6. 111 °C включает охлаждение и отменяет открытие нагрева;
   108 °C сохраняет охлаждение, 106 °C выключает.
7. Stop=TRUE при активном импульсе открытия: открытие снимается сразу,
   перед закрытием выдерживается пауза; подпитки выключены.
8. При остановке DrainRequest=TRUE и 30 %: слив включён;
   при 5 % или снятии запроса — выключен. При Enable=TRUE без Stop
   запрос слива игнорируется, начинается заполнение.
9. 76 % включает SecondLevel, 72 % удерживает, 69 % выключает.

Аварийные реакции, проверки достоверности датчиков, защитные блокировки
и автоматическое восстановление после аварий в этот вариант не добавлялись.
