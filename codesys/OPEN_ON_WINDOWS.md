# Открытие и сборка на Windows

## Что находится в архиве

- `BOILER_SIMULATOR.project`: исходный проект из репозитория, без изменений.
- `BOILER_SIMULATOR.Device.Application.2e148bd6-7613-4a70-8e94-46e3d62c8ddb.compileinfo`:
  предоставленные пользователем бинарные данные предыдущей компиляции, без изменений.
- `codesys/FB_Deaerator.xml`: PLCopen XML с новым функциональным блоком.
- `codesys/FB_Deaerator.st`: тот же код в читаемом текстовом виде.
- `codesys/README.md`: алгоритмы, тестовые диапазоны и сценарии симуляции.
- `codesys/compileinfo-report.json`: размер, SHA-256 и строки библиотек,
  извлечённые из compileinfo. Это диагностические сведения, не результат новой сборки.

## Как открыть

1. Распаковать весь архив в отдельный каталог на Windows.
2. Открыть `BOILER_SIMULATOR.project` через **File → Open Project** в CODESYS 3.5.
   `.compileinfo` оставить рядом с проектом с исходным именем. Сам по себе этот
   файл не открывается как проект, программа или текстовый исходник.
3. Если IDE сообщает о недостающих устройствах или библиотеках, установить
   соответствующие пакеты из официальных источников CODESYS и ОВЕН.
   В compileinfo встречаются библиотеки 3.5.17.0 и строка CODESYS V3.5 SP16;
   это не подтверждает точную версию компилятора или достаточность установки SP17.
   Проверить версию компилятора в Project Settings и версии в Library Manager.
4. Сохранить рабочую копию через Save As, прежде чем переносить новый алгоритм.
5. Выбрать Application и выполнить **Project → Import PLCopenXML**, указав
   `codesys/FB_Deaerator.xml`. Названия команд зависят от языка интерфейса IDE.
   Если такой FB уже есть, сначала проверить конфликт имён, а не заменять его вслепую.
   Альтернатива — перенос деклараций и реализации из ST по инструкции README.
6. Создать экземпляр `Deaerator : FB_Deaerator;` в существующем циклическом POU.
   Вызвать его один раз за цикл. Для первой проверки использовать внутренние
   переменные LevelPct, TemperatureC, PressureBar; физические I/O не подключать.
   Один импорт FB ещё не включает его в работающую программу.
7. Выполнить **Build → Rebuild**, проверить список ошибок и предупреждений.
   После изменений исходников IDE должна создать новые данные компиляции;
   приложенный старый compileinfo не доказывает совместимость нового блока.
8. Включить Simulation и выполнить сценарии из README. Использовать отдельную
   копию проекта без подключения к ПЛК. При недоступности симуляции для исходного
   устройства проверить блок в отдельном стандартном симуляционном проекте.

Для переноса на ПЛК210-13-CS требуется отдельная проверка конфигурации устройства,
модулей МВ210-102, каналов и библиотек. Исходный проект симулятора не был
автоматически преобразован под это оборудование.

## Ограничения текущей проверки

В облачной среде нет CODESYS, Wine и компилятора CODESYS. Проверено формирование
и чтение XML, соответствие тексту ST, целостность файла в ZIP. Реальная компиляция,
импорт XML в IDE и симуляция пока не выполнены. Старый compileinfo не заменяет
эти проверки и не содержит доступного здесь отчёта об успешной новой сборке.

Архив меньше исходного compileinfo благодаря ZIP-сжатию. Для хранения самого
бинарного файла в GitHub можно использовать Git LFS; архив для скачивания удобнее
прикрепить к GitHub Release. Веб-загрузка GitHub ограничена иначе, чем Git push.
В этой задаче файлы не публиковались в GitHub.
